## 4. Existing findings (already in the audit, status unchanged unless noted)

From audit section 1:

1. No licence system in the repository. The licence system was removed deliberately (see audit section 14). The licence entries in CLAUDE.md §5 and the master prompt are to be removed.
2. Google Drive sync was removed from the code in 1.2. `DriveSync.kt` is empty. `BuildConfig.GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` are defined but unused. The sync is planned again for 1.4 (LiveSync).
3. Failing test: `PhoneImportTest` expects English for `ja-JP,nl;q=0.5`, but Dutch is now index 9. Confirmed by the 2026-11-11 run (see section 2).
4. `/listimport` accepted uploads without an access code while the phone search was active. Up to 16 MB was reserved per request. **Changed in T-002** (see section 5); not yet validated on a device.
5. Silent HTTPS-to-HTTP downgrade in `TlsFallback.kt` after a certificate hostname mismatch. Affects Stalker login. Status: open.
6. Partly fixed phone-import security items: the failure counter is `AtomicInteger`, the code uses `SecureRandom`, and a Keystore hint exists in settings. Still open: the access code is 4 digits, the lock check and counter increment are not atomic, the comparison is not constant-time, and there is no warning about unencrypted transfer on the phone or TV side.
7. R8 keep rules sit in `app/src/main/_to_delete_keepRules/`. The FFmpeg decoder is loaded by reflection, so enabling R8 would likely break software audio. R8 is currently off. The `_to_delete_keepRules` folder is committed.
8. Version mismatch: Media3 1.11.1 with the Jellyfin FFmpeg decoder `1.9.0+1`. Not tested on a device.
9. Test count: 231 `@Test` functions in 31 files (audit count; not re-run in this baseline).
10. CI exists: `.github/workflows/build.yml` runs unit tests and a debug build on push. Actions are pinned to `@v4`, not to commit SHAs. The CI runs on Java 21, while the Gradle daemon toolchain is 25. Current run status: [PENDING: check the Actions tab; the audit expected it to be red since 1.1].

From audit section 8 (security):

- Phone-remote pages use plain HTTP and listen on all interfaces. Open. No warning found.
- Access code is 4 digits. Open.
- Failure counter: partly fixed (see item 6). Lock logic not atomic.
- `/listimport` without code while phone search is active: changed in T-002 (section 5).
- Backup via `GET /backup?code=…` (optionally with playlists and credentials) runs over HTTP. Open, follows from the HTTP issue.
- `Secrets` falls back to plaintext without an Android Keystore. Known; hint shown only in certain cases.
- TLS downgrade to HTTP: open (item 5).
- API keys: none in `Config.kt`; values come only from `secrets.properties` or user input in the app.
- Release APK in repo root: no keys included (checked in the audit).
- Google client secret could reach the APK via `secrets.properties`. Risk; field currently unused.
- App update: HTTPS required for GitHub assets; a custom update URL may use plain HTTP.
- Parental control PIN: 4 digits, with lock after failed attempts.
- Cleartext traffic allowed globally (required for IPTV; to be documented).
